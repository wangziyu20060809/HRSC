| 5 | 回 `front` 再办入住 | 放行，房态转「在住」 |

## 四、部署形态

| 项 | 说明 |
| --- | --- |
| 运行入口 | `src/room-status-mvp/server.py`（读 `PORT` 环境变量、绑定 `0.0.0.0`） |
| 技术栈 | FastAPI + uvicorn + SQLite(WAL)，无前端构建步骤 |
| 数据 | 云端实例为独立 SQLite，首次启动自动写入演示数据（24 间房 / 5 篇制度） |
| 分享码 | 平台侧要求跳转保留查询串，代码中由 `_go()` 统一处理 |

## 五、已知限制

1. **线上构建早于缺陷 D1 的修复**：线上版本岗位越权仍返回 HTTP 400（业务码仍是 40301），
   仓库代码已修复为 403（见《测试方案》5.3 节）。重新部署即可同步。
2. 云端数据为演示数据，多端同时操作会互相影响；验收复测请以本地实例
   （`DB_PATH=data/test8103.db`）为准。
3. 云端无模型密钥时助手自动降级为规则模式，回答仍正确，但不再做自然语言润色。
