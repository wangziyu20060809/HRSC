# 异常处置与维修房管理 —— 制度

适用岗位：前台、客房、质检；涉及外来施工时由运营管理审批。

## 一、报修与停用
房间出现设施故障（空调不制冷、马桶堵塞、门锁失灵、漏水等）时，任何岗位都可以报修，报修必须填写：

- 故障现象（具体到可复现，不要写"有点问题"）；
- 影响范围（能不能住人：可住但降级 / 完全不可住）；
- 预计修复时间；
- 责任岗位（工程 / 外委）。

报修后房间立即转"维修中"，退出可售库存。**不允许"先卖出去再说"** —— 让客人住进坏房，一次投诉的处理成本远高于一间房的空置成本。

## 二、维修完成后怎么回可售
维修完成 → 转"待清扫" → 清扫 → 已清扫 → 查房 → 可售。维修房不能直接从"维修中"跳到"可售"，因为施工会留尘、留味、动过布草，必须重走清扫与查房。

## 三、可住但降级的情况
例如景观被遮挡、部分设施受限但仍可入住：仍按报修处理并记录说明，是否继续售卖由运营管理决定。若继续售卖，需在前台侧写明"降级说明"，并对客人做价格或权益补偿说明；系统保留该说明，避免后续扯皮。

## 四、临时返工
已可售的房间在客人入住前发现瑕疵（例如布草被碰脏、临街噪音临时升高），可以执行"临时返工"：可售 → 待清扫，必须填写原因。返工同样走清扫与查房，不允许"擦一下继续卖"却不留痕。

## 五、客人投诉与房态的关系
客人投诉里最常见的三类都与房态相关：到店等待、房间未准备好、房间与承诺不符。处理要求：
1. 先核对系统房态流水，确认客人到店时房间到底是哪个状态（这是复盘的事实基础，不靠回忆）；
2. 若属于"已清扫当可售"导致的等待，记入房态错误案例，作为口径培训素材；
3. 补偿与承诺由前台按权限处理，超出权限升级当班主管，系统只记录不替代决策。

## 六、数据留存与权限边界
- 房态流水、查房结论、拦截记录、交接单不可删除，只能补充说明；
- 质检可查看全部流水，前台可查看本班次与本人操作，客房可查看本班组任务；
- 账号停用后历史操作记录仍保留，责任人可追溯；
- AI 助手只做只读核对与建议，任何改房态的动作都必须由有权限的人点击确认后才执行，助手自己不能改房态。
