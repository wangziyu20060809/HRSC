# 超时升级与交接规则 —— 制度

适用岗位：全部值班岗位；当班主管负责升级处置。

## 一、三条时效红线
| 环节 | 阈值 | 超时含义 |
| --- | --- | --- |
| 待清扫 → 清扫中 | 90 分钟 | 清扫积压，可售库存被占用 |
| 已清扫 → 开始查房 | 12 分钟 | 查房队列堵了，直接转化为客人等待 |
| 查房中 → 出结论 | 15 分钟 | 结论卡在个人手里，无人兜底 |

阈值可在管理端调整，但调整会写入审计，避免"把红线调宽"来美化指标。

## 二、升级路径
1. 超时 1 倍以内：员工端标黄，任务停留在原岗位，系统提示该房等待分钟数。
2. 超时 1–2 倍：标红，值班助手会在当班摘要里点名该房，并在交接班摘要中置顶。
3. 超时 2 倍以上：自动转为高优任务，交接班摘要标记"需主管处置"，同时计入超时统计。

升级不等于改房态。系统不会替人做查房结论，也不允许超时后自动置为可售——那等于用规则制造假房态。

## 三、交接班要交什么
交接单必须有四项：
1. **未完成事项**：待查房、待清扫、维修中的房间清单，带等待分钟数；
2. **风险提示**：超时房间、今天有预订但还未可售的房间；
3. **遗留问题**：客人投诉、设施异常、口径争议（例如某房客人要求延退）；
4. **数据口径**：当班拦截几次、平均清扫到可售多长时间，用于次日对照。

交接单由系统按当前房态自动生成草稿，值班人员补充人工说明后提交。提交后进入审计，可追溯到人和时间。

## 四、跨班次的口径一致性
- 交接班时不允许"口头说明代替系统状态"：口头说"这间房差不多可以了"，系统里依然是待查房，下一班就不能拿它开房。
- 上一班未完成的查房任务，下一班接手时任务归属自动转为"待接单"，不因换人而消失。
- 如果确实需要修正历史记录，只能新增一条带原因的说明事件，不能删除或覆盖原流水——流水是验收证据。

## 五、时效怎么算
"平均清扫到可售时长"= 从客房部提交"已清扫"到查房通过的时间差，按房间、按天统计，取近 7 天均值并给出 P90。只用均值会被个别长尾掩盖，所以 P90 一起看。
