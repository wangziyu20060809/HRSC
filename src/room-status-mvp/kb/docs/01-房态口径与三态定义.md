# 房态口径与三态定义 —— 制度

适用岗位：前台、客房、质检、运营管理。本文件是房态判断的唯一口径，冲突时以本文件为准。

## 一、为什么会有"客房准备好了，客人还在等"
当前断点不是没人干活，而是三套口径各自为政：客房部把房间标成"已清扫"，前台按这个标记认为可以入住，但查房还没做；客人到店后只能在大堂等，前台再去催客房、催质检，现场靠电话和口头确认收场。

管理层给过两个基线（访谈记录，需按样本复核）：高峰时段入住等待 38 分钟，目标压到 15 分钟；房态错误每周 24 次，目标降到 5 次。这两个数字都不接受"感觉好了"作为验收，必须由系统流水算出。

## 二、七个房态，一次性说清
- **待清扫（dirty）**：客人已退房或房间需要整理，尚未开始清扫。不可售。
- **清扫中（cleaning）**：客房部正在清扫，尚不能进入查房。不可售。
- **已清扫待查房（clean）**：客房部已提交清扫完成，但查房未通过。**不等于可入住**，不可售。
- **查房中（inspecting）**：质检或当班领班正在按检查项核对，尚未出结论。不可售。
- **可售（ready）**：查房通过，唯一允许办理入住的状态。可售。
- **在住（occupied）**：客人已入住，不可再分配。
- **维修中（blocked）**：设施故障停用，须记录原因与责任岗位，不参与分配。

## 三、最容易搞错的一条
"已清扫"是**清扫结论**，不是**可售结论**。清扫归客房部，可售归质检/领班。前台只有在看到"可售"时才可以把房间报给客人。

换句话说：清扫完成只是拿到了查房的入场券，不是通行证。前台若在"已清扫"状态下开房，系统会拦截并记录一次拦截（这条记录就是我们统计"房态错误"的来源）。

## 四、谁能改哪一步
- 客房部：待清扫 → 清扫中 → 已清扫待查房；报修；维修完成后重新进入待清扫。
- 质检/领班：已清扫 → 查房中 → 可售；查房不通过退回清扫中。
- 前台：可售 → 在住；在住 → 待清扫。
- 运营管理：可维护口径与阈值，但改房态同样留痕，不允许"静默修正"。

任何岗位都不能跳过查房直接把房间置为可售；也没有"管理员后门"——管理员操作同样写流水、同样生成审计记录。

## 五、同义词与常见问法
客人问"房间好了吗""能不能入住""还有空房吗"，本质上都在问同一件事：**这间房是不是可售**。前台口头说"房间已经打扫好了"只代表清扫完成，不代表可售，回答客人时不能用"打扫好了"替代"可以入住"。
